# Architecture
Browser Next.js/React/TypeScript + Tailwind CSS and shadcn-style Radix Slot/CVA Button → FastAPI REST / binary WebSocket → per-session ASR adapter → SQLAlchemy JSON records / SQLite (PostgreSQL URL supported).

FFprobe inspects input; FFmpeg decodes to signed PCM16 16kHz mono WAV. UUID paths, extension allowlist, byte/duration limits, process timeout and file/pipe-only protocol whitelist prevent remote media fetches. Metadata reports original properties. Playback fetches normalized WAV. Browser AudioContext at 16kHz decodes it; only samples whose playback time has elapsed are sent. No whole-file transcription occurs. One outstanding chunk applies backpressure; audio is not dropped. Slow inference can accumulate lag. Pause suspends AudioContext and stops dispatch; existing inference may finish. Resume is server-acknowledged before playback resumes. Stop finalizes the received prefix and clears caches. Only 1x is exposed; future speed changes must coordinate both clock and resampling.

Mock reports input duration only, never emergency statements. FunASR online shares model weights under an inference lock while cache and pending PCM belong to each adapter instance. Online model accumulates incremental text. Current utterance is one segment finalized at stop/EOF; VAD segmentation is future work. Native hotwords unsupported for the selected streaming adapter. Dictionary is stored, never silently used to guess flight numbers. Manual corrected_text never overwrites original_text.

Binary frame: little-endian PCM16 mono, 16kHz, maximum 2 seconds; JSON handles controls. Monotonic audio_time and server progress sequence are returned. Client measures chunk send→progress roundtrip, server measures inference time/RTF. This is not acoustic end-to-end latency. Resume within a live paused connection works; reconnect starts a new session (resume_supported=false), no replay deception. No durable recovery cache yet.

Entities: AudioSource (source/group/priority metadata in adapter contract); AudioFile; RecognitionSession; TranscriptSegment; EmergencyEvent and EmergencyEntity (evidence fields nested in event); HotwordDictionary; SystemConfiguration (environment-backed). Current lightweight store has kind/id/payload records, not a complete normalized production schema. PostgreSQL uses SQLAlchemy + psycopg; configure `postgresql+psycopg://...`. Migrations and concurrency hardening remain before production.

Event rules run only on genuine Final text, mark matches unverified, carry segment/time/text evidence and return null otherwise. Manual edits remain separate evidence and do not silently rewrite previous events. No dispatch API exists. LLM provider Protocol is an extension boundary; configured keys alone do not enable an untested provider.

Input extensions: UploadedFileAudioSource currently supplied by browser pipeline. Microphone, VHF, RadioGateway and SIP/RTP Protocols standardize source_id/sample_rate/timestamp/data. Future gateways terminate vendor protocols in isolated processes, jitter-buffer RTP, resample and feed independent recognition sessions. Channels gain group, priority and recording association; no hardware connection exists in Phase 1. SenseVoice/Whisper/OpenAI-compatible providers require distinct capability flags (offline vs online); offline results must never be presented as streaming.

Reference review adds `backend/review` and `/review`: private PDF uploads → bounded Poppler extraction or explicit manual excerpts → operator source verification → exact typo candidates bound to evidence → audio review acknowledgment → atomic correction and revision audit. SQL compare-and-swap rejects stale transcript writes. Reference kind/source metadata remain separate from audio evidence. Document text is untrusted data; it does not control system behavior. No LLM call or document instruction execution is involved. Numerical and command semantics are outside automatic mapping. User-supplied MH/T 4014-2003 version and matching clauses expose human checklist by channel context; no claim of current legal validity or automated compliance.

Real CPU ASR v0.3 uses Vosk small Mandarin: startup warms a shared immutable model; each session has its own recognizer and streaming PCM counter. A bounded semaphore controls real inference sessions (default one for free-tier memory). Endpoint results are persisted immediately with independent segment IDs, native word timestamps and available mean word confidence; empty results are not fabricated. Source-model text remains separate from whitespace-normalized display and human edits. Model installer pins SHA256, validates ZIP paths/symlinks/size and is reusable; model assets are included in the Docker image rather than downloaded during requests. Model failures are explicit health/WS states. Generic HTTP health is not model readiness. CI exercises both licensed actual speech and the real-model container health; Mock-based UI tests remain separate.
