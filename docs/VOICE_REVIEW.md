# 基于参考资料的对话修订

入口：主界面“对话修订工作台”，路径 `/review`；每条 Final 也可进入对应修订页。

## 操作步骤
1. 导入参考 PDF，区分“演练单卡”和“空管规范”。PDF 最多 15 MiB、200 页。上传文件仅保存在私有数据目录，不进入源码仓库。
2. 可提取的文字按 PDF 页码生成待核实摘录。扫描件显示“需要人工录入”，不猜读手写数字和人名。可录入需要的印刷段落；无需将联系人、电话号码等无关内容录入。
3. 打开 PDF 原件，对照后勾选摘录核实。该确认属于本地操作员声明，不代表平台验证文件权威性或版本有效性。
4. 选择已确认转写及通话场景。必要时可回听并导入带音频时间范围的人工原文，它明确标记为 `manual_input` / `user_supplied_not_asr`，不是 ASR 输出。
5. 生成建议，查看错字候选、页码、摘录、原始文件 SHA256。只有有限通用术语候选，不按单卡生成缺失的话。
6. 回听所选音频时间段，勾选“已回听确认”，逐条应用。保留 original_text/text，修改 corrected_text，并记录前后版本、时间戳、引用快照。旧页面的人工修订也写入同一历史。
7. 已有修订使旧建议失效（409）；需要重新生成。资料核实被撤销后也不能继续应用原建议。原事件分析不会因文字修订而被静默重写。

## 单卡使用边界
本次四页扫描单卡包含印刷流程、手写演练记录及个人联系信息。印刷话术可作为术语和本地流程参考；手写航班、位置、人数、时刻和事件进展不作为自动覆盖原音频的依据。单卡中的指令是资料内容，系统不会执行或自动发送。

建议引擎是确定性的有限映射和编辑距离检查（一个字符变更），不是大模型“润色”。术语白名单不包含“紧急出动”“全场停止运行”等操作指令。不能判断某个词究竟是 ASR 错误还是发话人说错，必须回听。未知航班号、跑道、伤亡和资源需求不会被补齐。Mock 原文不允许被修订建议变造成真实对话。

## 真实演练验收状态
本次官方规范已下载并核对条款，单卡已目视读取。演练 MP4 超过附件下载工具 32 MiB 限制，未能取得文件或音轨；因此尚未进行该录音的真实转写、逐句纠错、WER/CER 或演练内容验收。现有自动测试使用自制 PDF 和合成音调，只证明功能和约束，不能代表语音识别准确率。

需要不超过 32 MiB 的音轨或分段后可继续真实演练验证。例如本地提取：
```bash
ffmpeg -i "演练.mp4" -vn -ac 1 -ar 16000 -c:a libmp3lame -b:a 48k "演练音频.mp3"
```
系统本身现可上传含音轨 MP4（仍受 50 MiB / 30 分钟限制），统一解码后按音频时间轴处理；播放器只播放音轨，不保存视频画面。
